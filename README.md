# Детекция камней на доске Го

Кратко: проект реализует пайплайн подготовки данных, обучение классификатора патчей и минимальную веб‑обёртку для проверки ONNX‑модели. Модель классифицирует ячейки сетки как **empty / black / white** и экспортируется для инференса через `onnxruntime`.

---

## Описание проекта

**Цель**  
Определять наличие и цвет камня в каждой ячейке фиксированной сетки доски Го (по умолчанию \(19\times19\)). Результат — карта клеток с метками и confidence, пригодная для восстановления позиции на доске.

**Ключевые этапы**  
- Парсинг аннотаций Roboflow.  
- Генерация патчей по сетке и присвоение меток по IoU.  
- Стратифицированный сплит на train/val/test.  
- Обучение классификатора патчей.  
- Экспорт лучшей модели в ONNX и FastAPI‑сервис для проверки.

---

## Использованные инструменты и почему

**Язык и фреймворки**
- **PyTorch** — обучение, гибкость, цель задачи.
- **torchvision** — предобученные веса (MobileNetV2 использован в эксперименте).

**Подготовка данных**
- **Roboflow** — источник размеченных изображений; удобный экспорт аннотаций в текстовом формате.
- **Pillow, NumPy** — чтение/обработка изображений и патчей.

**Аугментации и баланс**
- **albumentations** (опционально) — реалистичные аугментации для повышения робастности.
- **WeightedRandomSampler** — борьба с дисбалансом классов при обучении(очень много пустых клеток и мало камней в соотношении 2000/1/1).

**Метрики и анализ**
- **scikit‑learn** — confusion matrix, classification_report, f1_score.

**Деплой и проверка**
- **ONNX + onnxruntime** — переносимость модели и быстрый inference в контейнере.
- **FastAPI + Uvicorn** — минимальная веб‑обёртка для демонстрации и тестирования.

## Метод обучения и теория

**Подход** — patch classification по сетке:
1. Из каждого изображения формируется регулярная сетка \(GRID\_N \times GRID\_N\).
2. Для каждой ячейки вырезается патч и ресайзится до фиксированного размера \(PATCH\_SIZE \times PATCH\_SIZE\).
3. Для разметки патча используется IoU с аннотациями: если IoU ≥ `THRESHOLD`, патчу присваивается класс аннотации; иначе — empty.
4. Полученные патчи используются для обучения классификатора изображений.

**Почему patch classification**  
- Простота реализации и интерпретации: каждая ячейка — независимый пример.  
- Не требует сложной детекции с bounding box regression, подходит для задач с регулярной сеткой (доска Го).

**Модель и loss**
- **Бэкбон:** MobileNetV2 (предобученный на ImageNet) — лёгкий, быстрый, достаточный для 64×64 патчей.
- **Классификатор:** полносвязный слой + softmax.
- **Loss:** взвешенная кросс‑энтропия с class weights, рассчитанными по обратной частоте классов, чтобы компенсировать дисбаланс.
- **Sampler:** WeightedRandomSampler для равномерного представления классов в батче.
- **Оптимизация:** Adam/AdamW, lr scheduler, ранняя остановка по val_f1.

**Почему class weights и sampler**  
Патчи empty значительно преобладали в исходных данных; веса и sampler помогают модели не «заучивать» только пустые клетки.

## Результаты эксперимента (включая ключевые логи)

**Окружение**  
- Device: **cuda**  
- Batch: **128**  
- Num workers: **2**

**Подготовка данных**  
- Preview patch counts (до фильтрации): `{empty: 29787, white: 3158, black: 3155}`  
- Saved patches: **8313** (распределение `{empty: 2000, white: 3158, black: 3155}`)  
- Split: **train 6490**, **val 700**, **test 1123**

**Обучение**  
- Архитектура: MobileNetV2 (предобученный)  
- Эпохи: **20**  
- Лучший `mean_f1` на валидации: **0.8833** (эпоха 19)

**Валидация (примерные значения по эпохам)**  
- val_acc ≈ 0.90  
- mean_f1_stones (высокие значения в конце обучения) ≈ 0.88

- **Classification report (test):**
  - **empty:** precision 1.00, recall 0.98, f1 0.99 (support 260)  
  - **black:** precision 0.88, recall 0.88, f1 0.88 (support 427)  
  - **white:** precision 0.88, recall 0.89, f1 0.89 (support 436)  
  - **accuracy:** 0.91, **macro avg f1:** ≈ 0.92

**Интерпретация**  
Модель хорошо распознаёт пустые клетки и достаточно уверенно различает чёрные и белые камни. F1 ≈ 0.88 для камней — хороший результат для ограниченного набора данных.

## Объяснение визуальных ошибок и почему в одном боксе может быть несколько камней

**Причины появления нескольких камней в одном боксе при визуализации:**
1. **Гранулярность сетки vs размер камня**  
   - Если сетка слишком крупная относительно расстояния между пересечениями или камни расположены близко, один патч может покрывать часть двух соседних пересечений. При отрисовке bbox по центру патча кажется, что в одном боксе несколько камней.
2. **Агрегация патчей в итоговую карту**  
   - Мы классифицируем патчи, а не детектируем отдельные объекты. При восстановлении позиции на доске используется правило агрегации (например, argmax по патчам или порог), и при перекрытии/смещении патчей может возникать дублирование.
3. **Аннотации и IoU**  
   - Если аннотации охватывают область, включающую несколько пересечений, или IoU threshold подобран нестрого, один патч может получить метку, соответствующую соседнему камню.
4. **Порог отрисовки confidence**  
   - Низкий порог приводит к рисованию всех уверенных и полу‑уверенных предсказаний, что визуально создаёт «скопление» рамок.
5. **Ошибки постобработки координат**  
   - Неправильное масштабирование/округление координат при ресайзе патчей и обратном маппинге на исходное изображение.

## Практическая демонстрация и команды

**Запуск веб‑обёртки (Docker)**
```bash
# собрать образ
docker build -t onnx-quick-check .

# запустить контейнер (монтирование модели)
docker run -d --name onnx-quick -p 8000:8000 \
  -v $(pwd)/app/model:/app/app/model:ro \
  onnx-quick-check

# логи
docker logs -f onnx-quick
```

**Тест инференса**
```bash
curl -X POST "http://localhost:8000/predict" -F "file=@/path/to/test.jpg" --output result.png
# открыть result.png — изображение с отрисованными рамками
```

## Ограничения и дальнейшие шаги

**Ограничения текущего подхода**
- Patch classification теряет точность при плотном расположении камней и при сильных вариациях ракурса/освещения.  
- MobileNetV2 — компромисс между скоростью и точностью; для максимальной точности стоит попробовать более мощные бэкбоны.  
- Постобработка и визуализация требуют аккуратной настройки порогов и правил агрегации.
---

## Заключение

Проект показал, что при аккуратной подготовке данных и использовании предобученного бэкбона можно получить стабильную модель с **~0.91 accuracy** и **F1 ≈ 0.88** для распознавания камней. Для повышения практической надёжности на реальных фотографиях рекомендую улучшить постобработку, усилить аугментации и рассмотреть переход к детекторной архитектуре при необходимости точной локализации.
